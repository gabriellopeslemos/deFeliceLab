# De Felice Lab — website

A static site (plain HTML/CSS/JS) for the De Felice Lab research program. The hero
section uses a WebGL fabric-ripple background rendered on a `<canvas>`, sampling
`assets/logosDeFeliceLab/textureBackground.webp`.

The pages that get deployed are **generated** from `src/` by `scripts/build_site.py`,
which produces the English site at `/`, the Portuguese site at `/pt/`, and inlines the
publication list into the HTML. The build has no third-party dependencies — plain
Python 3, no npm, no bundler.

## Site map

| URL               | Portuguese           | Source                  |
| ----------------- | -------------------- | ----------------------- |
| `/`               | `/pt/`               | `src/index.html`        |
| `/study/`         | `/pt/study/`         | `src/study.html`        |
| `/team/`          | `/pt/team/`          | `src/team.html`         |
| `/publications/`  | `/pt/publications/`  | `src/publications.html` |

The old `study.html`, `team.html` and `publications.html` URLs remain as redirect stubs
to their clean URLs, so links shared before the move keep working.

**Every path in the markup is absolute from the site root** (`/assets/styles.css`,
`/study/`), so the site must be served from the root of a domain — not from a
subdirectory like `usuario.github.io/repo/`.

## Building

Run this after editing anything in `src/`, `scripts/i18n.json`, or
`assets/publications.json`:

```bash
python scripts/build_site.py
```

It writes `index.html`, `study/`, `team/`, `publications/`, the whole `pt/` tree, and
the `.html` redirect stubs. All of those are generated — **edit `src/`, never them.**
Commit the generated output; there is no CI running the build.

## Running locally

The site **must be served over HTTP** — do not open the HTML directly as a `file://`
URL. The hero's WebGL shader loads a texture image, and browsers block that texture read
under `file://` (the canvas becomes "tainted" and the hero falls back to a flat navy
colour). The root-absolute asset paths need an HTTP root too.

Pick whichever you have installed. Run it from the project root:

```bash
python -m http.server 8777      # Python 3
npx serve -l 8777               # Node.js
npx http-server -p 8777
php -S localhost:8777           # PHP
```

Then open `http://localhost:8777/`.

## Requirements

- Python 3 to run the build (standard library only).
- Any static file server — see options above.
- A modern browser with **WebGL** enabled. Without WebGL, the hero gracefully falls back
  to a solid navy background.
- An internet connection on first load — fonts are pulled from Google Fonts. Everything
  else (styles, scripts, images) is local.

## Editing content

Page structure lives in `src/`. Translatable text is marked up in place:

- `data-i18n="key"` — the element's inner HTML comes from `scripts/i18n.json`
- `data-i18n-attr-<attr>="key"` — that attribute's value comes from the same file

The English text written inline in `src/` is what the `en` entry should say; the build
substitutes it from `i18n.json` for both languages, so **keep the two in sync** and add
every new key to both `en` and `pt`. The build prints a warning for any key it cannot
find. The `{{ALT_EN}}` / `{{ALT_PT}}` placeholders in the language toggle are filled in
with the current page's counterpart URL.

The language toggle is a pair of real links to the other language's URL — there is no
runtime translation, which is what makes the Portuguese pages indexable.

## Updating publications (ORCID)

The publication lists on `/` and `/publications/` are baked into the HTML at build time
from `assets/publications.json`, so they are indexable and render without JavaScript.
`assets/pubs.js` still runs and re-renders the same rows client-side, which keeps the
list correct if the JSON is updated without a rebuild.

`assets/publications.json` is generated locally by a Python script that queries the
ORCID public API — it is not regenerated automatically, so re-run it whenever the lab
publishes something new.

### One-time setup

1. Create/use an ORCID account at https://orcid.org and register an app under
   **Developer Tools** (https://orcid.org/developer-tools). Any redirect URI works
   (e.g. the site's URL) — it isn't used by the read-only flow this script uses.
2. Copy `.env.example` to `.env` and fill in:
   - `ORCID_CLIENT_ID` / `ORCID_CLIENT_SECRET` — from the app you just registered.
   - `ORCID_IDS` — comma-separated ORCID iD(s) (format `0000-0000-0000-0000`) of the
     lab's researchers whose publications should appear. Look one up at
     https://orcid.org/orcid-search if needed.
3. `.env` is git-ignored — never commit it.

### Running the script

```bash
python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r scripts/requirements.txt
python scripts/fetch_orcid_publications.py
python scripts/build_site.py
```

The first script writes `assets/publications.json`; the second bakes it into the pages.
Commit both so the live site reflects the update.

To add curated details ORCID doesn't provide (a topic tag, a full author byline, a
"why it matters" note, a citation count), edit `scripts/publications-overrides.json`
— keyed by DOI (lowercase) or, if a work has no DOI, its normalized lowercase title —
then re-run both scripts so the override gets merged in.

## Notes

- The hero WebGL background lives inline in `src/index.html` (a `<script>` near the end
  of the body) and is styled by the `.hero-canvas` / `.hero-scrim` rules in
  `assets/styles.css`. It was ported from `Hero Waves.dc.html`.
- Motion respects `prefers-reduced-motion`: with reduced motion enabled the hero paints a
  single static frame instead of the animated loop.
- `scripts/build_site.py` holds `BASE_URL`, the origin used for `hreflang` and the
  redirect stubs' canonical tags. Confirm it before relying on it in production — see
  `todoSEO.md`.
